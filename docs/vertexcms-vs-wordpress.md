# Преимущества VertexCMS перед WordPress

## Короткое позиционирование

VertexCMS проектируется как современная CMS для сайтов, лендингов и корпоративных страниц, где большинство базовых возможностей доступны из коробки: page builder, SEO, media, cache, API, PWA и AI-помощник.

Главное отличие от WordPress-подхода: VertexCMS стремится уменьшить зависимость типового сайта от большого количества сторонних плагинов.

## 1. Меньше зависимости от плагинов

В WordPress типовой корпоративный сайт часто требует отдельные плагины для SEO, кеша, page builder, форм, безопасности, редиректов, media-оптимизации, sitemap, Open Graph и иногда API-доработок.

VertexCMS закладывает эти функции как модули ядра:

- SEO meta;
- sitemap.xml;
- robots.txt;
- redirects;
- page cache;
- media library;
- visual page builder;
- activity logs;
- system info;
- API v1;
- AI assistant;
- PWA support.

Преимущество: меньше конфликтов между плагинами, меньше несовместимых обновлений, проще поддержка.

## 2. JSON-структура страниц вместо хранения HTML как источника истины

WordPress часто хранит контент как HTML или shortcode-структуры, особенно при использовании page builder-плагинов. Это усложняет миграции, API-выдачу, мобильные приложения и смену renderer.

VertexCMS хранит страницу как JSON schema:

```json
{
  "version": "1.0",
  "layout": "default",
  "settings": {},
  "sections": []
}
```

Преимущество: один структурированный источник данных, который можно рендерить в HTML, отдавать в API, мигрировать между версиями builder schema и использовать в AI-инструментах.

## 3. Современный backend на Laravel

VertexCMS строится на Laravel и использует привычные для современной PHP-разработки механизмы:

- Eloquent;
- migrations;
- seeders;
- middleware;
- service classes;
- queues;
- validation;
- Laravel cache;
- Laravel auth/session;
- testable application structure.

Преимущество: проект проще развивать командой, покрывать тестами и сопровождать как обычное Laravel-приложение.

## 4. API-first потенциал

WordPress имеет REST API, но многие сайты и плагины используют его непоследовательно. Данные page builder-плагинов часто неудобны для мобильных приложений.

VertexCMS заранее закладывает API v1 как стабильный контракт:

- публичные страницы;
- меню;
- media metadata;
- site settings;
- taxonomy в будущих версиях;
- token auth;
- OpenAPI schema.

Преимущество: мобильные приложения и внешние клиенты можно поддерживать без привязки к HTML-шаблонам админки.

## 5. AI-помощник как часть редакторского процесса

В WordPress AI-функции чаще добавляются отдельными плагинами, каждый из которых по-своему хранит ключи, логи и контекст.

VertexCMS планирует AI-модуль как встроенный слой:

- безопасное хранение API keys;
- provider registry;
- AI chat на странице создания/редактирования страницы;
- генерация текста;
- генерация SEO title/description;
- предложения структуры builder JSON;
- activity logs;
- permissions для AI-действий.

Преимущество: AI работает с реальной структурой страницы и не сохраняет изменения без подтверждения редактора.

## 6. Более предсказуемая безопасность

WordPress-сайты часто получают уязвимости через сторонние плагины и темы. Чем больше плагинов, тем больше поверхность атаки.

VertexCMS снижает риски за счёт:

- меньшего количества внешних расширений в базовом сценарии;
- permissions middleware;
- activity logs;
- запрета PHP-файлов в uploads;
- MIME и extension validation;
- SVG sanitization;
- CSRF-защиты;
- централизованной auth/RBAC модели.

Преимущество: меньше случайных точек входа и проще аудит.

## 7. Производительность из коробки

В WordPress высокая производительность часто достигается набором кеширующих и оптимизационных плагинов.

VertexCMS закладывает performance-модуль:

- page cache;
- settings cache;
- menu cache;
- view cache;
- ручная очистка кеша;
- server-rendered публичный frontend;
- минимум JavaScript на публичном сайте.

Преимущество: быстрый публичный сайт без тяжёлой SPA-логики и без обязательного набора performance-плагинов.

## 8. Чёткое версионирование

WordPress-плагины и темы часто обновляются независимо, что может ломать сайт при несовместимости версий.

VertexCMS вводит версионирование:

- core version;
- API version;
- builder schema version;
- module version;
- migration rules;
- release checklist.

Преимущество: обновления и миграции можно планировать предсказуемее.

## 9. Удобнее для кастомной разработки

WordPress отлично подходит для огромной экосистемы готовых решений, но кастомная архитектура часто упирается в legacy-паттерны, хуки, глобальное состояние и несовместимости плагинов.

VertexCMS ориентируется на Laravel-подход:

- явные сервисы;
- контроллеры;
- middleware;
- Eloquent-модели;
- миграции;
- понятные boundaries модулей.

Преимущество: проект легче развивать как индивидуальную CMS под конкретные бизнес-сценарии.

## Где WordPress сильнее

WordPress пока сильнее в областях:

- огромная экосистема тем и плагинов;
- большое сообщество;
- много готовых интеграций;
- WooCommerce;
- множество специалистов на рынке;
- зрелые managed hosting-решения;
- долгие годы production-проверки.

VertexCMS не должна копировать WordPress один в один. Сильная позиция VertexCMS - быть более простой, управляемой и современной CMS для сайтов, которым нужны скорость, встроенные базовые функции, API, AI и меньше плагинной зависимости.

## Итог

VertexCMS выигрывает не количеством готовых плагинов, а архитектурной предсказуемостью:

- меньше зависимостей;
- структурированный JSON-контент;
- встроенные SEO/media/cache/API/AI/PWA направления;
- Laravel-архитектура;
- более понятная безопасность;
- удобная база для кастомной разработки.
