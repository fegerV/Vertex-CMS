# Мониторинг 404 ошибок

**Мониторинг 404** — это функция автоматического отслеживания страниц, которые возвращают ошибку "404 Not Found" при попытке доступа.

## Зачем нужно отслеживать 404 ошибки

Ошибка 404 возникает, когда пользователь или поисковый робот пытается перейти по несуществующей ссылке. Это негативно влияет на:

### Пользовательский опыт (UX)
- ❌ Посетители видят страницу ошибки вместо нужного контента
- ❌ Увеличивается показатель отказов (Bounce Rate)
- ❌ Снижается доверие к сайту
- ❌ Теряются потенциальные клиенты/продажи

### SEO показатели
- ❌ Поисковые роботы тратят краулинговый бюджет на несуществующие страницы
- ❌ Теряется ссылочный вес с внешних источников
- ❌ Ухудшается индексация сайта
- ❌ Возможны проблемы с ранжированием

## Как работает мониторинг в Vertex SEO Pro

### Автоматическое логирование

Система автоматически записывает все 404 ошибки в журнал:

1. **Перехват запроса** — Middleware отслеживает все запросы к сайту
2. **Фиксация ошибки** — При получении статуса 404 данные сохраняются в БД
3. **Сбор информации**:
   - URL, который вызвал ошибку
   - Referrer (откуда пришел пользователь)
   - User Agent (браузер/робот)
   - Дата и время ошибки
   - Количество повторений

### Группировка ошибок

Ошибки автоматически группируются для удобства анализа:
- Одинаковые URL объединяются
- Считается количество попыток доступа
- Определяются наиболее критичные страницы

## Работа с журналом 404

### Просмотр логов

Перейдите в **SEO → 404 Monitor** чтобы увидеть:

| Столбец | Описание |
|---------|----------|
| **URL** | Адрес несуществующей страницы |
| **Попытки** | Сколько раз запрашивалась страница |
| **Последний раз** | Когда была последняя ошибка |
| **Referrer** | Откуда перешли на эту страницу |
| **Тип** | Человек или поисковый робот |

### Фильтрация и сортировка

Используйте фильтры для поиска конкретных ошибок:
- По дате (за сегодня, неделю, месяц)
- По количеству попыток (только частые ошибки)
- По типу трафика (люди vs роботы)
- По источнику (внутренние ссылки vs внешние)

## Исправление 404 ошибок

### Метод 1: Создание редиректа (Рекомендуется)

Если страница была перемещена или удалена навсегда:

1. Найдите ошибку в списке 404
2. Нажмите кнопку **"Создать редирект"**
3. Укажите новый URL назначения
4. Выберите тип редиректа (301 для постоянного)
5. Сохраните изменения

**Пример:**
```
Старый URL: /old-blog/post-123
Новый URL: /blog/new-post-name
Тип: 301 (Постоянный)
```

### Метод 2: Импорт всех 404 в редиректы

Для массового исправления:

1. Перейдите во вкладку **"Импорт 404"**
2. Выберите фильтр (например, "Более 10 попыток")
3. Нажмите **"Импортировать выбранные"**
4. Для каждого URL укажите страницу назначения
5. Подтвердите создание редиректов

### Метод 3: Восстановление страницы

Если страница была удалена ошибочно:
1. Создайте новую страницу с тем же URL
2. Восстановите контент из резервной копии
3. Ошибка 404 исчезнет автоматически

### Метод 4: Исправление битых ссылок

Если ошибка возникает из-за неверной ссылки на сайте:
1. Найдите источник в столбце "Referrer"
2. Откройте страницу-источник на редактирование
3. Исправьте или удалите битую ссылку
4. Сохраните изменения

## Настройка уведомлений

### Email уведомления

Настройте автоматические оповещения о критичных ошибках:

1. Перейдите в **SEO → Настройки → Уведомления**
2. Включите опцию **"Уведомлять о 404 ошибках"**
3. Настройте порог срабатывания:
   - Минимальное количество попыток
   - Период проверки (ежедневно, еженедельно)
4. Укажите email для уведомлений

### Пороговые значения

Рекомендуемые настройки:
- **Высокий приоритет**: >50 попыток за день
- **Средний приоритет**: >10 попыток за день
- **Низкий приоритет**: >3 попыток за день

## Анализ источников 404

### Внутренние ссылки

Если пользователи переходят по битым ссылкам внутри вашего сайта:

1. Откройте ошибку в деталях
2. Посмотрите список referrer'ов
3. Если источник — ваш сайт, исправьте ссылку
4. Проверьте, нет ли похожих ошибок в других местах

### Внешние ссылки

Если на несуществующую страницу ссылаются другие сайты:

1. Найдите внешние источники в логах
2. Создайте редирект на релевантную страницу
3. (Опционально) Свяжитесь с владельцами сайтов для обновления ссылок

### Поисковые роботы

Если 404 возникает при сканировании поисковиками:

1. Проверьте, есть ли ссылка в sitemap.xml
2. Удалите URL из карты сайта
3. Используйте инструмент Google Search Console для исключения

## Профилактика 404 ошибок

### Перед удалением страницы

1. ✅ Проверьте, есть ли входящие ссылки на страницу
2. ✅ Создайте редирект на новую версию ДО удаления
3. ✅ Обновите внутренние ссылки на сайте
4. ✅ Исключите URL из sitemap.xml

### При изменении структуры URL

1. ✅ Составьте карту старых и новых URL
2. ✅ Настройте пакетные редиректы через Regex
3. ✅ Протестируйте все редиректы перед запуском
4. ✅ Мониторьте логи после изменений

### Регулярный аудит

Проводите проверку сайта на 404 ошибки:
- **Еженедельно** — для крупных интернет-магазинов
- **Ежемесячно** — для контентных сайтов
- **После любых изменений** — обновление дизайна, миграции

## Лучшие практики

### ✅ Делайте
- Быстро создавайте редиректы для популярных 404
- Исправляйте внутренние битые ссылки
- Используйте кастомную страницу 404 с навигацией
- Регулярно анализируйте логи ошибок

### ❌ Не делайте
- Не игнорируйте множественные попытки доступа
- Не редиректите все 404 на главную страницу
- Не оставляйте битые ссылки в навигации
- Не забывайте про мобильную версию

## Кастомная страница 404

Создайте полезную страницу ошибки 404:

```html
<h1>Страница не найдена</h1>
<p>К сожалению, запрашиваемая страница не существует.</p>

<!-- Полезные ссылки -->
<ul>
    <li><a href="/">Вернуться на главную</a></li>
    <li><a href="/catalog">Перейти в каталог</a></li>
    <li><a href="/search">Поиск по сайту</a></li>
</ul>

<!-- Форма поиска -->
<form action="/search" method="get">
    <input type="text" name="q" placeholder="Что вы искали?">
    <button type="submit">Найти</button>
</form>
```

Это уменьшит негативный эффект от ошибок и поможет пользователям найти нужный контент.
